# Декларація використання штучного інтелекту

## Лабораторна робота №1
Інструменти: Gemini і Claude. Gemini використано для чернеток коду профілювання (`pandas`, `jupytext`) і скрипта схеми `architecture_v0.png`; Claude — для перевірки ноутбука й звіту на відповідність вимогам методички. Поставлені завдання: підготувати чернетку коду перевірки порожніх полів, рядків із пробілів і некоректних дат; зіставити структуру звіту з вимогами методички. Внесок автора: постановка завдань і вибір між запропонованими варіантами. У результаті знахідки поділено на підтверджені порушення й потенційні ризики, нульову ціну перевірено разом з `is_active`, а непідтверджені пояснення причин дублікатів до звіту не включено. Перевірка: ноутбук виконано повністю (`jupytext --execute`); кількості рядків, ID дублікатів, відсутніх батьків, `UA H` і некоректних дат звірено з виведенням pandas на файлах пакета. Виправлена помилка: перша версія перевірки порожніх рядків шукала колонки типу `object`, а в pandas 3 текст має тип `str`, тому перевірка нічого не знаходила; помилку виявлено порівнянням з окремим підрахунком.

## Лабораторна робота №2
Інструменти: Gemini і Claude. Gemini використано для чернеток DDL, завантажувача на `psycopg` і тестів; Claude — для звірки коду й звіту з вимогами методички та підготовки відтворюваного скрипта перебудови. Поставлені завдання: підготувати чернетку завантаження через `COPY` у staging і таблиці `audit.row_decisions`; порівняти код конвеєра і звіт із методичкою та перелічити розбіжності. Внесок автора: постановка завдань, вибір між запропонованими варіантами та перевірка результатів запусків. Прийняті в роботі правила: `UA H` відхиляється як `INVALID_CURRENCY`, `DD/MM/YYYY` читається явно як UTC, ціна перевіряється разом з `is_active`, суми звіряються окремо за валютою. Перевірка на локальному PostgreSQL 16: юніт-тести правил, регресійний тест на пакеті S08, звірка ключів accepted ↔ core в обидва боки, rollback-тест; відхилені ID збігаються з реєстром проблем Лаби 1.

## Лабораторна робота №3
Інструмент: Claude. Поставлені завдання: підготувати чернетки трьох VIEW (`v_daily_orders` через три CTE, `v_running_orders`, `v_latest_customer_order`) і скрипт запуску файлів комплекту з вимірюваннями; пояснити рядки `EXPLAIN (ANALYZE, BUFFERS)`. Внесок автора: постановка завдань, перевірка результатів запусків і пояснення запитів. Перевірка на власних даних S08: готові перевірки викладача дали PASS (`daily_exact_match`, `running_exact_match`, `latest_order_exact_match`, `benchmark_same_result`), суми звірено окремо для UAH та EUR, ручний розрахунок двох замовлень збігся з рядком денного звіту. Цікавий випадок: `SUM(DISTINCT total_amount)` дав правильну суму, але лише тому, що всі 345 сум доставлених замовлень місяця різні; це перевірено окремим запитом, тому такий запит не вважається виправленням JOIN. Виправлена помилка: у першій версії скрипта запуску функції fish посилалися на локальну змінну шляху, якої функції не бачать; помилку помічено до запуску, шляхи замінено на відносні.

## Лабораторна робота №4
Інструмент: Claude. Поставлені завдання: підготувати чернетки трьох функцій `student.py` (перевірка пакета за manifest, GET-запити з обмеженими повторами, обхід сторінок за курсором) за контрактом методички й відкритими тестами; заповнити `results.md` числами з власних запусків. Внесок автора: постановка завдань, перевірка результатів запусків і пояснення коду. Перевірка: 26 відкритих тестів без змін — passed; реальний сценарій «збій → успіх → повтор» на локальному API й PostgreSQL дав 0 / 5450 / 0 нових записів, кількості збіглися з `expected_counts.json`; окремо перевірено відхилення зміненого й неповного пакета. Виправлена помилка: у першій версії `results.md` для групи тестів повторів було вказано 12 замість фактичних 11; виправлено за збереженим виводом pytest. Цікавий невдалий кейс: під час огляду структури `api_keys.json` Claude вивів у сесію сам ключ, бо він є назвою поля JSON. Ключ діє лише для локального навчального сервера; у Git, звіт і логи він не потрапив, що підтверджено скануванням відстежуваних файлів.
